> 用途：每周模拟面试时按此提问，检查是否达到大厂算法岗标准
> 更新：随项目进展补充"已能答"和"仍不能答"的标记

## 使用方法

每周日取 5–8 题，**不给准备时间**，要求连续回答。答不上的记下来，下周优先补。

大厂面试的真实节奏是：**候选人说 60 秒，面试官追问 2 层**。所以每题的评估标准不是"能不能说出来"，而是"能不能扛住追问"。

评分：
- 🟢 能讲清且扛住 2 层追问
- 🟡 能说结论，但追问就露馅
- 🔴 说不清

## 第二组：技术深度（15 分钟，核心区）

### Q4. 什么是 RRF？为什么用它而不是加权求和？
**期望**：RRF 只用排名不用分数，因为 BM25 分和 cosine 分不可比。
**追问**：
- "写出公式" → `score(d) = Σ 1/(k + rank_i(d))`，k 通常 60
- "k 的作用是什么？" → 平滑，k 大则各 rank 贡献接近，k 小则头部主导
- "你的项目里 RRF 怎么用的？" → Hybrid 内部三路融合
- **"同源文档重复命中会怎样？" → 这是关键区分点**，见 Q5

`[未准备]`

### Q5. 一道菜被切成 5 个 chunk，5 个都命中，naive RRF 会出什么问题？
**期望**：分母不变，但同一文档被加 5 次分，会霸榜。
**追问**：
- "C9 怎么解决的？" → `_rrf_merge` 用 `node_id` 归并，只取最佳 rank
- "这对你的工作有什么用？" → `rrf_chunk_hits` 天然是 novelty 信号
- **"如果不用 node_id 归并，你会怎么改？"** → 考察能否举一反三

> 这题是检验"是否真读过代码"的试金石。答不出说明只看了文档。

`[未准备]`

### Q6. 你的证据充分性判定，具体怎么算？
**期望**：说出三个条件——实体覆盖、连通覆盖、预算合规。
**追问**：
- "为什么需要连通覆盖？举个反例" → "文档 A 有鸡肉，文档 B 有土豆，但可能是两道不同的菜"
- "连通性怎么算？复杂度？" → BFS，`O(|V|+|E|)`
- **"如果图里没有这条路径，但文本里能推理出来呢？"** → 这是判定的边界条件，**必须想好**：说明你的方法是必要条件不是充分条件，会有 false negative
- **"为什么不直接用 Neo4j 的 shortestPath 查一下？"** → 因为那是**查询**图数据库，不是**判定**已检索的证据。你的证据是文本 chunk + 部分路径，需要在证据子图上判定

`[未准备]`

### Q7. 为什么要做预算控制？预算设多少？
**期望**：说明成本不对称——Graph 检索内部调 LLM（`understand_graph_query`），比 Hybrid 贵。
**追问**：
- "预算是 2 够吗？" → 要能说"这是实验变量（A4 消融验证），不是先验假设"
- "怎么知道多花一次检索值不值？" → 边际增益 `Δ` = 新增覆盖 / 成本
- **"贪心什么时候会失效？"** → 两个工具单独无效但组合有效时。**你的 Benchmark 里要有这类样本**

`[未准备]`

### Q8. 你的实体识别怎么做的？
**期望**：词典匹配（3229 个已知实体），不是 NER、不是 LLM。
**追问**：
- "为什么不用 LLM？" → 封闭实体集，词典更准、零成本、可复现
- "同义词怎么办？" → `synonyms` 字段有 520 条非空
- **"如果用户说'鸡'而不是'鸡肉'呢？"** → 这是词典匹配的硬伤，要诚实承认，并说明你的处理（子串匹配 / 别名字典 / 降级到向量召回）
- **"中文分词噪音怎么办？"** → Aho-Corasick 多模式匹配可以避免分词

## 第三组：实验设计（10 分钟，最能区分水平）

### Q9. 你怎么证明你的方法比 Baseline 好？
**期望**：不是"准确率涨了 X%"，而是分层验证——先证判定器有效（AUC），再证端到端。
**追问**：
- "判定器的 ground truth 哪来的？" → 人工标注 60 条
- "人工标注可靠吗？" → 说清标注规范、是否双人
- **"如果判定器 AUC 高，但端到端没提升，怎么回事？"** → 说明问题出在生成侧，不是检索侧。**这个回答很重要，说明你理解 pipeline 的归因**

`[未准备]`

### Q10. 你的 Benchmark 会不会偏向图检索？
**期望**：会，原设计就是。所以用"图 + 文本双来源"过滤。
**追问**：
- "双来源怎么定义？" → 图能查到 + 文本能读到
- **"只保留双来源都支持的，会不会删掉太多样本？"** → 会，所以从 200 降到 80–100 是可接受的取舍
- **"合成问题有模板痕迹，模型可能靠模板作弊吗？"** → 需要人工改写做对照实验

`[未准备]`

### Q11. 你怎么定义"路径命中"？
**期望**：不存具体路径，存"最小证据集"（同一 recipe 连到两个 ingredient）。
**追问**：
- "为什么不存路径？" → 等价路径有多种，存路径会误判合法答案
- **"如果 Agent 返回了路径但中间节点不对呢？"** → 只要两端实体正确且连通，中间节点不参与判定

## 第四组：杀手问题（提前想好，这组最容易崩）

### Q12. 你的改进，本质不就是把 C9 的 Bug 修了吗？
**危险等级**：🔴 最高。这题答不好，整个项目归零。

**期望答案结构**：
1. **承认事实**：B0 到 B3 的提升确实主要来自修复
2. **分开归因**：所以我把 B3（修复后的 One-shot）作为**唯一有效对照**，B0 只用于缺陷记录
3. **给出证据**：Ours vs B3 才是我的贡献，这个对比里修复是常量
4. **主动出示消融**：A1（去连通性）如果掉点，才证明我的方法有独立贡献

**绝对不能说**："B0 到 Ours 提升了 30%"——这是把两件事混在一起，面试官会当场质疑。

`[未准备]`

### Q13. 这和 Self-RAG / CRAG / Adaptive-RAG 有什么区别？
**期望**：不能只说"我用实体覆盖"。要说出**判定 vs 打分**的区别。
- Self-RAG：LLM 生成反思 token，**概率性**
- CRAG：分类器给 correct/incorrect/ambiguous，**文本层面**
- 你：图上连通性，**确定性可判定**

**追问**："那你的方法是不是只在有图的时候有用？" → 是的，这是边界。对无结构数据不适用。**主动承认边界比掩盖强。**

`[未准备]`

### Q14. 如果 Always-Combined 准确率比你高，你怎么解释？
**期望**：说明这是可预期的——Always-Combined 是质量上界，你的目标是在**成本约束**下逼近它。
**追问**：
- "那你的贡献是什么？" → Pareto 改进：同等质量下成本更低，或同等成本下质量更高
- **"成本差多少才算有意义？"** → 要有具体数字，不能含糊
- **"如果成本只省 5%，值得吗？"** → 诚实回答：不值得，说明方法边界太窄

`[未准备]`

### Q15. 你的方法失败了会怎样？
**期望**：能说出具体的失败模式，而不是"不会失败"。
- 假阴性：文本能推但图没连 → 误判不足，多花一次检索
- 假阳性：图上连了但语义无关 → 误判充分，早停
- 贪心失效：单工具无增益但组合有效

**追问**："你怎么检测这些失败？" → 人工看 trace，分类统计
